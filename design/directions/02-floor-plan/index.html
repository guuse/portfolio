How it's built

Doorsnede A–A · building section, read from the ground up

Decisions

Toelichting · keyed notes
  1. N1

    k3s in a VM, not LXC

    Kubernetes in a container needs privileged mode and cgroup hacks, and breaks on upgrades. A VM snapshots as one unit.

  2. N2

    Home Assistant next to the cluster, not in it

    USB passthrough to a VM is one line. Into a pod it means a device plugin and node pinning, and it breaks on reschedule.

  3. N3

    TLS at the proxy, plain HTTP in HA Core

    So there's always a LAN fallback that works with no cert, no tailnet, no proxy.

  4. N4

    One flat applications/ folder

    The root app manages itself. No bootstrap/projects/apps sprawl.

  5. N5

    No backups beyond snapshots

    A conscious trade-off: everything is rebuildable from git, and the guide is good enough to do it in an afternoon.

Learned the hard way

revisions · each one changed the drawing
  1. A

    Rev. A · disk

    Disk-pressure at 30 GiB on a 500 GB SSD

    Ubuntu's guided LVM install allocated half the disk and parked the rest as free space. Kubelet panicked. Fix: one lvextend, zero downtime.

  2. B

    Rev. B · disk, again July 2026

    lvextend on the host does nothing for the guest

    QEMU never hears about it. Resize through Proxmox or qm resize.

  3. C

    Rev. C · DNS

    Public DNS broke on every Linux node

    MagicDNS had no global nameserver, so *.ts.net resolved and nothing else did. My Mac kept working because macOS ignores resolv.conf.

  4. D

    Rev. D · certificates

    Home Assistant doesn't renew its own certs

    A monthly automation restarts the Let's Encrypt add-on, then NGINX. HA Core itself never restarts.

  5. E

    Rev. E · Zigbee · went fine

    The mesh survived the Pi → VM move with zero re-pairing

    Same stick, full backup, “Restore backup” on the scary ZHA dialog, never “keep new settings”.

Rules of 99

Commander in the browser, with full rules enforcement.

  • Wraps Forge's open-source Java rules engine headless behind a WebSocket/JSON gateway. All ~33k cards are data, and commander tax and 21 commander damage are engine-native.

How I work

five house rules
  1. 1

    Write it down where the code lives

    Every repo of mine has a context file and ADRs. Future me and the AI agents both start by reading.

  2. 2

    Git is the source of truth

    For infrastructure, for side projects, even for house hunting.

  3. 3

    Boring tech, sharp edges filed off

    k3s, Postgres-or-SQLite, Astro. The interesting part is the problem.

  4. 4

    Automate the second time

    Not the first, not the third.

  5. 5

    Let Claude do the boring part

    Judging 200 listings, writing the tag bump, drafting the runbook. I review.
