Homelab platform

01illustration

A small, production-style Kubernetes platform on an old laptop under the TV.

An old laptop with the lid shut runs Proxmox, a single-node k3s cluster and everything I build. It’s managed the way I’d run a client platform: one git repo, Argo CD syncing every app, wildcard TLS, and no open ports. If the disk dies, I rebuild it from the repo in an afternoon.

how it works

  1. Proxmox runs two VMs: Ubuntu with k3s for the apps, and Home Assistant OS (see the next project). The laptop battery doubles as a UPS.

  2. Argo CD watches one repo with an app-of-apps root that manages itself. Each app is one Application file; adding a repo is adding a file.

  3. GitHub Actions builds every app to an immutable commit-SHA image on GHCR. Argo CD Image Updater commits the new tag back to git, and Argo rolls it out.

  4. cert-manager gets one wildcard Let’s Encrypt certificate via Cloudflare DNS-01; Traefik serves it for every app, so no app needs its own certificate.

  5. Three ways in, all opt-in: the private tailnet by default, a Cloudflare Tunnel with Access for a few public hostnames, and Tailscale Funnel for a party-night URL.

decisions

k3s in a VM, not LXC
Kubernetes in a container needs privileged mode and breaks on upgrades.
Home Assistant next to the cluster, not in it
USB passthrough to a VM is one line.
Snapshots, no off-site backups
Everything is rebuildable from git, by choice.

learned the hard way

  • Disk pressure at 30 GiB on a 500 GB SSD: the Ubuntu installer allocated only half the disk. One lvextend, zero downtime.
  • Growing a disk on the host doesn’t tell the guest. Resize through Proxmox, not lvextend.
  • MagicDNS without a global nameserver broke public DNS on every Linux node.

one app, one file

Every app on the platform is one small file like this. Argo CD keeps the cluster in line with it.
