Homelab

The same patterns I use at work, on one node: an old laptop under the TV running k3s, Argo CD and Home Assistant.

Role
Everything, in my spare time
Period
2026
Type
Personal

Context

I wanted one place for my side projects, and somewhere to try things before I recommend them at work. An old laptop with the lid shut runs Proxmox, a single-node k3s cluster and Home Assistant.

It has its own domain, real certificates and no open ports. The laptop battery doubles as a UPS.

From git push to running

At home, main deploys directly, by choice. At work, production follows release tags instead.

  • GitHub Actions builds every commit into an image on GHCR, tagged with the commit SHA.
  • Argo CD Image Updater watches GHCR and commits the new image version to git; Argo CD syncs and the pods roll over.
  • One repo holds an app-of-apps root that also manages Argo CD itself. Adding an app is adding one file, like the one below.

Getting in

The tailnet is the default. The other two ways are opt-in, per app.

  • Tailnet: my devices reach Traefik over Tailscale. DNS for my domain points at the tailnet, so the names only resolve to something reachable from my own devices.
  • Cloudflare Tunnel with Access: a few apps are public on a normal hostname, behind a login, without opening a port.
  • Tailscale Funnel: a temporary public URL, for example for the quiz at a party.
  • TLS everywhere: one wildcard Let’s Encrypt certificate through Cloudflare DNS-01, served by Traefik for every app.

Inside the box

The laptop has 16 GB of memory. Proxmox runs two virtual machines:

  • Ubuntu with k3s for the apps, with 10 GB.
  • Home Assistant OS with 3 GB, with the Zigbee USB stick passed straight through.
  • The host keeps about 2 GB, and about 1 GB is spare.

I take a snapshot before every upgrade. Everything else can be rebuilt from git.

Home Assistant

  • It runs in its own VM next to the cluster, not in it: passing the Zigbee stick through to a VM is one line of config.
  • HTTPS goes through an NGINX proxy, with plain HTTP on the home network as a fallback. A monthly automation renews the certificate.
  • I moved it from a Raspberry Pi with a full backup restore, and the whole Zigbee mesh came across without re-pairing a single device.
  • Dashboards and automations live in git. A tablet on the wall shows the dashboard.

Trade-offs

  • One node, no redundancy. If the laptop dies, everything is down until I rebuild it. That’s why I’m turning it into three nodes with second-hand mini PCs.
  • Snapshots, no off-site backups. Everything is rebuildable from git, by choice. Data that isn’t in git would be lost with the disk.
  • k3s in a VM, not in an LXC container. Kubernetes in a container needs privileged mode and tends to break on upgrades, so I accept the overhead of a VM.

Lessons

  • Symptom
    Disk pressure in the k3s VM at about 30 GiB used, on a 500 GB SSD.
    Cause
    The Ubuntu installer gave the root volume only half of the disk.
    Fix
    lvextend and a filesystem resize inside the guest. No downtime.
  • Symptom
    I grew the VM’s disk on the host, but the guest still saw the old size.
    Cause
    A raw lvextend on the Proxmox host doesn’t tell QEMU about the new size.
    Fix
    Grow the disk through Proxmox (qm resize), then run growpart, pvresize and lvextend inside the guest.
  • Symptom
    Public DNS stopped resolving on every Linux node.
    Cause
    Tailscale MagicDNS was on without a global nameserver.
    Fix
    Set a global nameserver in the tailnet’s DNS settings.
