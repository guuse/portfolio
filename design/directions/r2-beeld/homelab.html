Homelab

The patterns I use at work, on one node at home.

Personal · 2026

An old laptop under the TV, lid shut, runs Proxmox with a single-node k3s cluster and Home Assistant. I use it for my side projects, and to try things before I recommend them at work. It has its own domain and real certificates, and nothing on it is reachable from the internet unless I open it on purpose. The laptop’s battery acts as a UPS.

From git push to running

At home, main deploys directly. At work, production only follows release tags; here I skip that on purpose.

GitHub Actions builds each commit into an image on GHCR, tagged with the commit SHA. Argo CD Image Updater notices the new image and commits its version back into the app’s repo, and Argo CD syncs. Because that commit lands in the same repo, the CI workflow ignores the deploy/ folder with paths-ignore; the lessons below explain why.

One repo holds an app-of-apps root that also manages Argo CD itself, and adding an app is adding one file. It runs 15 applications now.

Getting in

The tailnet is the default: my own devices reach Traefik over Tailscale. DNS for my domain points at the tailnet, so the names only resolve to something reachable from my devices.

Two other ways in are opt-in, per app. A few apps are public on a normal hostname through a Cloudflare Tunnel with Access in front, so there’s a login and no open port. For a party, Tailscale Funnel gives a temporary public URL, for example for a quiz.

Every app gets TLS from one wildcard Let’s Encrypt certificate, issued through Cloudflare DNS-01 and served by Traefik.

Inside the box

The laptop has 16 GB of memory. Proxmox gives 10 GB to an Ubuntu VM with k3s and 3 GB to a Home Assistant OS VM; the host keeps about 2 GB and about 1 GB is spare.

10 GB k3s3 GB Home Assistant~2 GB host~1 GB spare

I take a snapshot before every upgrade, and everything else can be rebuilt from git. Running k3s in a VM rather than an LXC container costs some overhead, but Kubernetes in a container needs privileged mode and tends to break on upgrades. One node also means no redundancy, so the next step is three second-hand mini PCs.

Home Assistant

Home Assistant runs in its own VM next to the cluster rather than in it, because passing the Zigbee USB stick through to a VM is one line of config. HTTPS goes through an NGINX proxy, with plain HTTP on the home network as a fallback, and a monthly automation renews the certificate.

I moved it from a Raspberry Pi with a full backup restore, and the whole Zigbee mesh came across without re-pairing a single device. The dashboards and automations live in git, and a tablet on the wall shows the dashboard.

Lessons

  • Symptom
    Builds kept running in a loop, each one producing a new image (August 2026).
    Cause
    Image Updater commits the new tag back into the same repo, so CI built that commit, produced a new tag, and Image Updater committed again.
    Fix
    CI ignores deploy/ with paths-ignore.
  • Symptom
    The k3s node hit disk pressure at about 30 GiB.
    Cause
    The VM’s disk was 64 GiB, but the Ubuntu installer gave root only half of it.
    Fix
    Grow the disk in Proxmox (qm resize), then run growpart, pvresize and lvextend inside the guest.
  • Symptom
    Public DNS stopped resolving on the Linux VMs on my tailnet.
    Cause
    Tailscale MagicDNS was on without a global nameserver.
    Fix
    Set a global nameserver in Tailscale’s DNS settings.
